# P0 — Implementação para ns-3.48

**Estado:** código criado e revisto face à API publicada do ns-3.48; **ainda não compilado nem executado no WSL do grupo**.

## Objetivo e limitações

O P0 valida separadamente:

1. **Previsão matemática independente:** FSPL(d0) + log-distance, com d0=1 m e expoente n=3;
2. **Modelo usado pelo canal ns-3:** `LogDistancePropagationLossModel::CalcRxPower`, com a **mesma instância do objeto** configurada no canal `YansWifiChannel`;
3. **Receção PHY Wi-Fi:** média de RSS de frames efetivamente descodificados na interface do autocarro (`MonitorSnifferRx`), **quando existirem**.

O cenário instala um AP e uma STA IEEE 802.11g, sem UDP, sem buffer e sem movimento contínuo. A STA **muda de posição por degraus**, ficando estacionária dois segundos em cada distância. É um ensaio de laboratório de propagação, não o cenário de mobilidade B10.

A trace de RSS existe **apenas para frames descodificados** (beacons/probes/gestão, sem qualquer tráfego UDP). Assim, `decoded_frames_at_sta=0` resulta em campos de RSS vazios: **não preencher com zero nem tratar ausência como potência de 0 dBm**. Este teste **não mede** PDR, cobertura útil, taxa de aplicação, associação ou velocidade do autocarro.

**Geometria:** a separação real 3D é `sqrt(h^2+1,5^2)`. Para `h=0`, `d=1,5 m`, não 0 nem 1 m. Isto explica por que os resultados não devem ser comparados por igualdade de linha com o `theory.csv`, onde a coluna `distance_m` representa distâncias 3D definidas diretamente.

## Executar no WSL

O repositório **não é uma instalação do ns-3**. O simulador está noutra pasta e o script transfere apenas o ficheiro `src/b10-p0-propagation.cc` para o respetivo `scratch/`. Não modifica a `main` nem os ficheiros originais do ns-3.

Na raiz de `COMOV_NS3_B`, depois do merge do PR:

```bash
git pull
bash scripts/run_p0.sh /caminho/para/ns-3.48
```

Atenção: usar o caminho **real** da instalação, que pode ser `~/ns-allinone-3.48/ns-3.48`, `~/ns-3.48` ou outro.

O script:

1. Confirma que existe `./ns3` e `scratch/`;
2. Copia o programa, sem sobrescrever um ficheiro alheio;
3. Invoca `./ns3 run "scratch/b10-p0-propagation --standard=11g --csv=..."`;
4. Grava `out/p0/p0_11g.csv`;
5. Executa `scripts/evaluate_p0.py` para recalcular a teoria e verificar coerência.

Se quiseres executar uma vez com 802.11a, **apenas como controlo opcional**, usar:

```bash
bash scripts/run_p0.sh /caminho/para/ns-3.48 11a
```

O script de avaliação toma 20 dBm, alturas 4,0/2,5m e n registado no CSV. Se forem alterados via flags do C++, passar os novos valores também ao avaliador.

## Resultados esperados e testes

- CSV com **7 linhas** de separações horizontais diferentes.
- Colunas `theoretical_pr_dbm`, `ns3_model_pr_dbm` e `model_minus_theory_db`.
- Erro de modelação esperado `|delta| <= 0,01 dB` — verificações aritméticas independentes, com arredondamento CSV.
- Pelos menos alguns frames descodificados a curta distância (0, 5, 10m); se não houver, inspecionar canal, MAC, tipo de trace e potência.
- Para receções disponíveis, discutir `phy_minus_model_db`, geralmente próximo do valor calculado numa baseline sem ganhos adicionais. O avaliador assinala diferença superior a 1,5 dB e **não a esconde**.
- A ausência de frames a grandes distâncias é um resultado do recetor e do modelo PHY, **não prova por si só** a fronteira de cobertura do serviço.
- O programa deve terminar sem exceções; qualquer erro de compilação ou mismatch da trace impede afirmar que P0 foi validado.
